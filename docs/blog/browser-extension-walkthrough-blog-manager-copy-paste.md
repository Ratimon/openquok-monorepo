<h2>What is the OpenQuok Chrome extension social media scheduler?</h2>

<p>The <strong>OpenQuok Chrome extension</strong> is a <strong>social media scheduler browser extension</strong> for Google Chrome. It uses the <strong>side panel</strong>—not only a toolbar popup—so you can draft, schedule, and publish to channels you already connected in your OpenQuok workspace.</p>

<p>It is also the <strong>browser session bridge</strong> OpenQuok uses when the server cannot finish alone: <strong>Skool</strong> cookie connect, <strong>Reddit</strong> member handoff at due time, and <strong>directory launch</strong> autofill for PeerPush and Uneed. You keep one calendar, one approval model, and one product profile store.</p>

<p>Start here: <a href="/browser-extension">Browser extension landing</a> · Install and limits: <a href="/docs/installation/chrome-extension">Browser extension docs</a>. <strong>Microsoft Edge</strong> ships the same Chromium package as Chrome; <strong>Firefox</strong> uses a separate build and sidebar UI. <h2>Why Skool and Reddit use a Chrome extension—not OAuth</h2>

<p>For a long time, community builders asked for one thing: <strong>schedule Skool posts</strong> from the same calendar they use for Threads, LinkedIn, or TikTok. The blocker is not your scheduler. The blocker is the platform.</p>

<p><strong>Skool does not give schedulers a standard OAuth posting connect</strong> the way Meta or Google do. There is no reliable “register a developer app, paste client ID and secret, publish every post from the server” path for every team. OpenQuok still schedules Skool from the workspace—but <strong>connect</strong> needs your live session in Chrome. The extension reads session cookies while you stay signed in on skool.com. OpenQuok stores the session encrypted and publishes scheduled posts from the server at due time. That is <strong>browser extension</strong> connect, not OAuth. Rules: <a href="/docs/platforms/connect-rules">Connect rules</a> · Setup: <a href="/docs/social-integration/skool">Skool integration</a> · Families: <a href="/docs/social-integration">Social integration overview</a>.</p>

<p><strong>Reddit is a different extension story.</strong> On default OpenQuok (including self-host), we do <strong>not</strong> register a Reddit OAuth app for workspace posting. You add Reddit as a <strong>manual channel</strong> in Add Channel. OpenQuok drafts and schedules like other networks, but at due time the row becomes <strong>awaiting member</strong>. You finish on reddit.com. The same Chrome extension helps with <strong>Copy</strong>, <strong>Open submit</strong>, and <strong>Autofill</strong>. It does <strong>not</strong> post to Reddit from the backend, and it does not read Reddit cookies for API access. See <a href="/docs/social-integration/reddit">Reddit setup</a> and <a href="/blog/ai-agents-for-reddit-promote-without-getting-banned">AI agents for Reddit: promote without getting banned</a>.</p>

<p>So one extension serves two honest needs:</p>

<ul>
<li><strong>Skool</strong> — close the “no public OAuth” gap so <strong>server-side schedule</strong> can run after cookie connect.</li>
<li><strong>Reddit</strong> — close the “no full auto-post from the server” gap so you keep <strong>human submit</strong> on reddit.com with less copy-paste friction.</li>
</ul>

<p>Most other networks still use <strong>OAuth</strong> or your own <strong>API key</strong> (for example Bluesky or Dev.to). Only then does the side panel act as a fast composer on channels you already connected in the dashboard. The extension does not replace Add Channel for OAuth. Walkthrough: <a href="/docs/channels/connect">Connect a channel</a>.</p>

<p>Community owners kept asking for Skool on the same calendar as everything else. We did not want a fake “connected” badge with no real publish path. We ship one Chrome extension: connect Skool with your real session, schedule in OpenQuok, and let the server publish when the post is due—with images and <a href="/docs/creating-posts/threads-and-comments">follow-up comments</a> where Skool allows them.</p>

<h2>Skool post scheduler: extension connect in practice</h2>

<p><strong>Can you schedule Skool community posts inside Skool only?</strong> Skool’s public help center covers events, pins, and live calls—not a native “schedule this feed post for Tuesday” feature. Creators use schedulers that rely on a live browser session when OAuth is not available.</p>

<p>OpenQuok’s Skool flow:</p>

<ol>
<li>Install the Chrome extension and stay signed in on <strong>skool.com</strong> in the same Chrome profile.</li>
<li>In the dashboard, choose <strong>Add Channel → Skool</strong> and approve cookie access when prompted.</li>
<li>OpenQuok validates the session, stores it encrypted, and can register refresh so cookies update about every 24 hours.</li>
<li>Schedule Skool posts in the composer like other channels—OpenQuok publishes from the server at the due time, including images where supported.</li>
<li>Optional: add scheduled <a href="/docs/creating-posts/threads-and-comments">follow-up comments</a> on the same Skool post when your group allows them.</li>
</ol>

<p><strong>Important:</strong> This is cookie-based connect, not Skool OAuth. Anyone with access to your Skool session can post as you. Sign out on shared devices and read Skool’s terms before you connect.</p>

<p>Docs: <a href="/docs/social-integration/skool">Skool integration</a> · Channel page: <a href="/channels/skool">Skool on OpenQuok</a>.</p>

<h2>Reddit scheduler: plan in OpenQuok, publish on reddit.com</h2>

<p><strong>Does OpenQuok post to Reddit from the server?</strong> No. Reddit is a <strong>manual channel</strong>. OpenQuok never stores Reddit login on the server. You add Reddit from Add Channel, draft markdown in the workspace, and schedule like other networks.</p>

<p>When the post is due, status becomes <strong>awaiting member</strong>. The extension can:</p>

<ul>
<li><strong>Copy</strong> caption and optional title.</li>
<li><strong>Open submit</strong> to the right community or profile URL when Settings define <code>r/name</code> or <code>u/name</code>.</li>
<li><strong>Autofill</strong> title and body on the Reddit submit page when the UI still matches what OpenQuok expects.</li>
</ul>

<p>Autofill does <strong>not</strong> click Post. You review, submit, then <strong>Mark posted</strong>. If Reddit redesigns submit, fall back to Copy and paste. That manual step is intentional if you want to avoid bot-like behavior—see <a href="/blog/ai-agents-for-reddit-promote-without-getting-banned">promote on Reddit without getting banned</a>.</p>

<p>Body limit is <strong>10,000</strong> characters in the markdown editor. Media on the row supports your handoff workflow; the server does not upload attachments to Reddit’s API at publish time.</p>

<p>Guides: <a href="/docs/social-integration/reddit">Reddit setup</a> · <a href="/docs/cli-examples/reddit">CLI examples</a> · <a href="/channels/reddit">Reddit channel</a> · <a href="/docs/platforms/media-rules">Media rules</a>.</p>

<h2>AI in the browser: Humanizer, Gemini in Chrome, WebMCP, and agents</h2>

<p>Teams ask whether built-in browser AI replaces a scheduler extension. It does not. The layers stack.</p>

<h3>OpenQuok AI and Humanizer (copy quality + calendar)</h3>

<p>OpenQuok’s signed-in composer includes AI drafting options. The free <a href="/tools/humanizer">Humanizer</a> rewrites stiff AI copy in the browser before you schedule—no account required for the tool itself. That addresses <strong>voice</strong>, not <strong>channel permissions</strong>.</p>

<p>Keep Humanizer in a tab while you work: rewrites stay on-device, then copy the result into the Social side panel or dashboard composer. See <a href="/blog/how-openquok-humanizer-rewrites-a-draft-in-the-browser">How OpenQuok Humanizer rewrites a draft in the browser</a> and the <a href="/docs/installation/chrome-extension">browser extension</a> guide for scheduling flows.</p>

<p>After Humanizer, pick channels in the side panel and move the paragraph into a dated post on Skool, Threads, or other connected channels—or use <strong>Schedule with OpenQuok</strong> from a fresh selection.</p>

<h3>Gemini in Chrome (built-in assistant)</h3>

<p>Google ships <strong>Gemini in Chrome</strong> in the sidebar for summaries, comparisons, and Connected Apps (Gmail, Calendar, Maps, YouTube, and more). Where your plan and region allow, <strong>auto browse</strong> can run multi-step web tasks with confirmations on sensitive steps.</p>

<p>Use Gemini to read the web faster. Use OpenQuok to hold which channels fire at which times—and who in the workspace approved the post.</p>

<p>Official references: <a href="https://www.google.com/chrome/ai-innovations/" rel="noopener noreferrer" target="_blank">Chrome AI innovations</a>, <a href="https://support.google.com/chrome/answer/16821166" rel="noopener noreferrer" target="_blank">Auto browse help</a>, <a href="https://blog.google/products-and-platforms/products/chrome/gemini-3-auto-browse/" rel="noopener noreferrer" target="_blank">Google’s Gemini in Chrome update</a>.</p>

<h3>WebMCP (structured page tools for agents)</h3>

<p><strong>WebMCP</strong> is a proposed standard: web pages register tools with schemas so agents invoke <code>checkout</code> or <code>filter_results</code> instead of guessing button labels. Chrome documents developer trials and local testing flags; some desktop agents already call similar APIs under names like “site tools.”</p>

<p>WebMCP improves reliability on sites that adopt it. Skool sessions, Reddit submit forms, and paid directory flows will still need human-in-the-loop handoffs for a long time—exactly where this extension sits.</p>

<p>Spec: <a href="https://developer.chrome.com/docs/ai/webmcp" rel="noopener noreferrer" target="_blank">WebMCP on Chrome for Developers</a> · Proposal: <a href="https://webmachinelearning.github.io/webmcp/docs/proposal.html" rel="noopener noreferrer" target="_blank">WebMCP API proposal</a>.</p>

<h3>Agents, MCP, and Chrome DevTools MCP (builders vs operators)</h3>

<p>OpenQuok <a href="/docs/getting-started-for-mcp">MCP</a> and <a href="/tools/skill-builder">Skill Builder</a> let agents list integrations and schedule posts through your API when channels are connected. That is server-shaped automation.</p>

<p>Separately, developers experiment with <strong>Chrome DevTools MCP</strong> servers so coding agents inspect console, network, and DOM state. That stack is for building and debugging automations—not for replacing a social scheduler extension. When built-in Chrome AI changes, verify behavior against <a href="https://gemini.google/overview/gemini-in-chrome/" rel="noopener noreferrer" target="_blank">Gemini in Chrome overview</a> and <a href="https://www.google.com/chrome/ai-innovations/" rel="noopener noreferrer" target="_blank">Chrome AI innovations</a> before you change production workflows.</p>

<p>DevTools MCP is for building and debugging. The OpenQuok extension is for operators scheduling and handing off—different jobs.</p>

<h2>Self-host: extension ID and trust boundary</h2>

<p>Self-host teams build from the monorepo and wire extension IDs on the web app so the dashboard can reach the install your users actually use.</p>

<ul>
<li><strong>Google Chrome</strong> — <code>extension/dist/</code>, side panel, <code>externally_connectable</code>. Guide: <a href="/docs/configuration-web/browser-extension-chrome">Extension (Chrome)</a>.</li>
<li><strong>Microsoft Edge</strong> — same Chromium zip as Chrome; Edge assigns its own CRX ID. Add <code>edge:…</code> to <code>VITE_OPENQUOK_BROWSER_EXTENSION_IDS</code>. Guide: <a href="/docs/configuration-web/browser-extension-edge">Extension (Edge)</a>.</li>
<li><strong>Firefox</strong> — <code>extension/dist-firefox/</code>, sidebar UI, page <code>postMessage</code> bridge (no <code>externally_connectable</code>). Add <code>firefox:…</code> to <code>VITE_OPENQUOK_BROWSER_EXTENSION_IDS</code>. Guide: <a href="/docs/configuration-web/browser-extension-firefox">Extension (Firefox)</a>.</li>
</ul>

<p>Use a single <code>VITE_OPENQUOK_BROWSER_EXTENSION_ID</code> for one Chromium install only, or <code>VITE_OPENQUOK_BROWSER_EXTENSION_IDS=chromium:…,edge:…,firefox:…</code> when you ship more than one store listing. See <a href="/docs/configuration-web">Web configuration</a>.</p>

<p>Skool connect does not need Skool secrets on the server. Directory autofill reads profile data over the same dashboard link. Privacy: <a href="/privacy-policy">Privacy Policy</a>.</p>

<p>After each build, run the Social and Directory verification steps in <a href="/docs/installation/chrome-extension">Browser extension</a> and the checklists on your browser’s configuration page.</p>

<h2>Limits shipped today (read this before you expect magic)</h2>

<ul>
<li>Extension composer posts through the workspace API. Posting directly from a live platform tab for cookie channels is planned but not in the current build.</li>
<li>Reddit will not become full server OAuth publish on default self-host.</li>
<li>Directory launches do not add a social posting channel to the calendar.</li>
<li>Skool cookie connect can break if Skool changes access—monitor and reconnect.</li>
</ul>
